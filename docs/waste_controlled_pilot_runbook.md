# 통제된 연출 파일럿 운영 안내

*W6용. 사진 30~60장을 반나절에 만들 수 있게 쓴 절차서.*

> **이건 사람 대상 실험이 아니다.**
> 참가자를 모으지 않는다. 누가 무엇을 먹었는지 관찰하지 않는다. 얼굴을 찍지
> 않는다. 학번·이름·연락처를 적지 않는다.
>
> 준비한 음식의 일부를 **직접 덜어 내서** 잔반 상태를 만든다.

> **`docs/waste_pilot_collection_runbook.md`와 다른 문서다.**
> 그쪽은 실제 급식소에서 사람이 먹고 남긴 것을 모으는 절차이고, 참가자 번호와
> 끼니 번호가 나온다. 이 문서는 그 앞 단계 — **촬영 조건만 밥플래너 시연과
> 맞춰 보는 통제 실험**이다. 두 절차를 섞지 않는다.

---

## 0. 이 파일럿으로 알 수 있는 것과 없는 것

| | |
|---|---|
| **알 수 있다** | LeFood로 만든 모델이 우리 카메라·식판·음식에서도 신호를 내는가 |
| **알 수 있다** | 촬영 조건이 바뀔 때 성능이 얼마나 떨어지는가 (domain gap) |
| **알 수 없다** | 학생들이 실제로 얼마나 남기는가 |
| **알 수 없다** | 메뉴별 실제 잔반률 |

두 번째 칸은 사람의 식사 행동을 봐야 답할 수 있고, 이 파일럿은 그걸 하지
않는다. **보고서에서 "실제로 먹고 남긴 사진"이라고 쓰지 않는다.** 정확한
표현은 `연출된 잔반 상태` 또는 `staged leftover conditions`다.

---

## 1. 준비물

- 주방 저울 1 g 단위 이상 (0.1 g이면 더 좋다)
- 밥플래너 시연에 **실제로 쓸 식판 또는 접시**
- 음식 3~5종. 실제 급식 메뉴에 가까울수록 좋다
  (예: 밥 / 국물 없는 반찬 / 국물 있는 반찬 / 튀김류)
- 스마트폰 1대 — 시연에 쓸 기종이면 가장 좋다
- 촬영 배경 1개 (식탁, 트레이 매트 등). **바꾸지 않는다**
- 음식을 덜어 낼 집게·국자·빈 그릇
- 기록용 노트 또는 매니페스트 CSV 파일

**한 번에 다 하려 하지 않는다.** 음식 1종을 끝까지 해 보고 절차가 맞으면
나머지를 진행한다.

---

## 2. 촬영 자리 먼저 고정

사진을 찍기 전에 자리를 정한다. **첫 파일럿에서는 촬영 변동을 크게 만들지
않는다.** 조명·각도·거리를 다 흔들면 성능이 나빴을 때 무엇 때문인지 알 수
없다. 강건성은 다음 문제다.

1. 식판을 놓을 자리를 배경에 표시한다 (마스킹 테이프면 충분하다)
2. 폰을 드는 높이를 정한다. 식판 전체가 프레임에 들어오는 가장 낮은 높이
3. 각도를 정한다 — **위에서 내려다보는 각도**를 권한다
4. 그 상태로 시험 촬영 1장. 식판 네 모서리가 다 보이면 됐다
5. 조명을 정한다. 실내등만, 또는 창가 낮 시간 중 하나. **섞지 않는다**

이 다섯 개를 정했으면 파일럿이 끝날 때까지 바꾸지 않는다. 바꿔야 하면
`capture_session_id`를 새로 만든다.

---

## 3. 식기 무게 재기 (식기 종류마다 한 번)

```
1. 저울에 빈 식판을 올린다
2. 무게를 적는다              예: 식판 A = 412 g
3. 같은 식판을 다시 두 번 더 잰다
4. 세 값이 1 g 안에서 같으면 됐다. 아니면 저울 위치를 바꿔 다시
```

**tare(영점) 버튼을 써도 되고 빼기로 계산해도 된다.** 다만 하나로 정하고
끝까지 같은 방식을 쓴다. 섞으면 어떤 표본이 어느 방식이었는지 나중에 알 수
없다.

> **음식 질량에 식기 질량이 섞이면 안 된다.** 이게 이 파일럿에서 가장 흔한
> 실수다. 식판 412 g이 섞이면 잔반률이 통째로 틀린다.

---

## 4. 표본 하나 만들기

표본 하나에 4~5분이면 된다.

### 4-1. 배식량 재기

```
1. 식판을 저울에 올리고 tare (또는 빈 식판 무게를 적어 둔다)
2. 음식을 담는다. 실제 1인분에 가깝게
3. 무게를 적는다  →  served_edible_mass_g
```

`served_edible_mass_g`는 **먹을 수 있는 부분의 질량**이다. 뼈, 껍질, 씨처럼
애초에 먹지 않는 것은 담지 않는다. 담았다면 그 무게를 빼고 적는다.

### 4-2. 목표 잔반 상태 정하기

표본을 만들기 **전에** 목표 구간을 정한다. 사진을 찍고 나서 "이 정도면
0.7쯤"이라고 눈으로 매기지 않는다.

| 구간 | 남길 목표 | 예 (배식 300 g) |
|---|---|---|
| B0 | 0~20% | 0~60 g |
| B1 | 20~40% | 60~120 g |
| B2 | 40~60% | 120~180 g |
| B3 | 60~80% | 180~240 g |
| B4 | **80~100%** | **240~300 g** |

**B4를 넉넉히 만든다.** 모델이 무너지는 구간이 거기다. 관문이 요구하는 최소는
6개지만 10개 이상이면 좋다.

### 4-3. 덜어 내기

```
1. 목표 잔량이 되도록 음식을 빈 그릇으로 덜어 낸다
2. 남은 접시를 저울에 올린다
3. 목표 범위에 들어왔는지 본다. 아니면 조금 더 덜거나 되돌린다
```

**자연스럽게 보이려고 억지로 흩뜨리지 않아도 된다.** 다만 국물을 한쪽으로만
몰거나 음식을 한 덩어리로 쌓아 두면 실제와 너무 멀어진다. 접시 위에 고르게
남기는 정도면 충분하다.

### 4-4. 사진

```
1. 표시해 둔 자리에 식판을 놓는다
2. 정해 둔 높이·각도에서 1장
3. 화면에서 초점이 맞았는지, 그림자가 음식을 가리지 않는지 확인
4. 흔들렸으면 다시 찍는다. 흔들린 사진을 쓰지 않는다
```

**식후 사진만 찍는다.** 지금 production 요청이 식후 이미지 하나이기 때문이다.
식전 사진은 이 파일럿에서 쓰지 않는다.

사람 손이나 얼굴이 프레임에 들어가지 않게 한다. 들어갔으면 지우고 다시 찍는다.

### 4-5. 잔량 재기

```
1. 사진을 찍은 그 상태 그대로 저울에 올린다
2. 무게를 적는다  →  leftover_edible_mass_g
```

**사진을 찍은 뒤에 잰다.** 재느라 접시를 옮기면서 음식이 흐트러지면 사진과
무게가 어긋난다.

### 4-6. 기록

매니페스트에 한 줄 적는다 (§6).

## 5. 반복 계량 — 최소 5개 표본에서

측정이 얼마나 흔들리는지 모르면 모델 오차를 해석할 수 없다.

```
1. 표본 5개를 골라 (구간이 서로 다르면 좋다)
2. 같은 상태를 저울에서 내렸다가 다시 올려 **3회** 잰다
3. 세 값을 모두 적는다  →  repeat_index 0, 1, 2
```

같은 표본의 반복은 `sample_id`를 그대로 두고 `repeat_index`만 바꾼다.
`repeat_index > 0`인 행은 모델 평가에 쓰지 않고 **측정 오차 계산에만** 쓴다.

> 여기서 나온 표준편차가 **모델 MAE의 바닥**이다. 모델 MAE가 이 값과
> 비슷하면 "잘 맞혔다"고 말할 수 없다 — 저울도 그만큼 흔들린다.

템플릿: `docs/templates/waste_controlled_pilot_manifest_template.csv`

| 열 | 예 | 설명 |
|---|---|---|
| `sample_id` | `pilot_w6_0001` | 순번. **비식별.** |
| `source` | `controlled_staged_pilot` | 고정값. 다른 값이면 거절된다 |

| `leftover_edible_mass_g` | `265` | 잔량 (식기 제외) |

| `repeat_index` | `0` | 반복 계량 번호. 기본 0 |
| `device_model` | `Galaxy S24` | 선택 |
| `resolution` | `4032x3024` | 선택 |
| `orientation` | `overhead` | 선택 |
| `lighting` | `indoor_ceiling` | 선택 |
| `note` | | 선택 |

**적으면 안 되는 것:** 이름, 학번, 연락처, 이메일, 계정, 얼굴 여부, 주소,

## 8. 점검 (QC)

표본 30개쯤 모였으면 한 번 돌린다.

```
.venv-waste\Scripts\python.exe research\waste_estimation\scripts\w6_pilot_audit.py ^
  --manifest research\waste_estimation\data\private\w6_pilot\manifest.csv ^
  --images research\waste_estimation\data\private\w6_pilot\images
```

출력에서 확인할 것:

```
STATUS: PILOT_READY        ← 이게 나와야 평가로 넘어간다
표본 34 / 범주 4 / 고잔반 9
구간 분포 [8, 6, 5, 6, 9]
거절 0
```

`PILOT_INSUFFICIENT`가 나오면 어느 관문이 걸렸는지 함께 나온다. **부족한 채로
평가하지 않는다** — 표본 12개로 잰 MAE는 반드시 성능처럼 인용된다.

| 관문 | 최소 |
|---|---|
| 유효 표본 | 30 |
| 음식 범주 | 3 |
| 고잔반(≥0.8) | 6 |
| 잘못된 정답 | 0 |
| 중복 | 0 |

거절 사유가 나오면 그 행을 고친다. **지우지 말고 고친다.** 못 고칠 이유가
있으면(사진이 흔들렸다 등) 그 행을 빼고 왜 뺐는지 `note`에 남긴다.

## 9. 평가

관문을 통과했으면:

```
.venv-waste\Scripts\python.exe research\waste_estimation\scripts\w6_evaluate.py ^
  --manifest research\waste_estimation\data\private\w6_pilot\manifest.csv ^
  --images research\waste_estimation\data\private\w6_pilot\images
```

이 스크립트는 **LeFood DEVELOPMENT 398건으로만 모델을 맞춘다.** 파일럿
라벨은 학습에 들어가지 않고, 임계값도 게이트도 파일럿을 보고 조정하지 않는다.
그 경로가 코드에 없다.

## 10. 정리

```
1. 남은 음식을 처리한다
2. 저울과 식판을 닦는다
3. 사진 개수와 매니페스트 행 수가 맞는지 센다
4. images 폴더를 저장소 밖에도 한 벌 백업한다
```

사진을 지우기 전에 QC를 한 번 더 돌린다. 다시 찍을 수 없는 표본이 대부분이다.

## 자주 나오는 질문

**Q. 음식을 실제로 먹으면서 만들면 안 되나요?**
그 순간 사람 대상 관찰이 되고, 이 파일럿의 범위를 벗어난다. 덜어 내서 만든다.

**Q. 국물은 어떻게 재나요?**
국물도 먹을 수 있는 부분이라 포함한다. 다만 흘리기 쉬우니 배식·잔량 모두
같은 그릇에서 재고, 옮기지 않는다.

**Q. 밥이 접시에 붙어서 안 떨어져요.**
붙은 것도 잔반이다. 억지로 긁어내지 말고 그대로 잰다.

**Q. 목표 구간에 정확히 안 맞아요.**
맞출 필요 없다. 목표는 구간을 고르게 채우기 위한 것이고, 정답은 저울 값이지
목표값이 아니다.

**Q. 30개를 다 못 모으면요?**
관문이 막는다. 그게 정상이다. 모델 평가는 다음에 하면 된다.

**Q. 사진에 손이 나왔어요.**
지우고 다시 찍는다. 사람이 나온 사진은 쓰지 않는다.
