# Stage A2 수동 정답 작성 규칙

**이 규칙은 예측을 보기 전에 정했다.** 결과를 본 뒤 규칙을 바꾸지 않는다.
규칙을 뒤에 맞추면 오차는 줄어들지만 그 숫자는 아무것도 재지 않은 것이 된다.

## 대상

| | |
|---|---|
| 영상 | `vtest.avi` (opencv/opencv `samples/data`, Apache-2.0) |
| 해상도 | 768 x 576 |
| 프레임률 | 10 fps |
| 전체 | 795 frames / 79.5초 |
| **정답 구간** | **0 ~ 29초, 1초 간격 30개 시점** (frame 0, 10, 20, ..., 290) |

전체 795프레임에 정답을 붙이지 않는다. 첫 정량 평가에 필요한 만큼만 붙이고,
어디까지 붙였는지를 명시한다. 예측도 같은 구간으로 잘라서 비교한다.

**이것은 급식소 영상이 아니다.** 보행자 통로를 내려다보는 고정 카메라이고,
"사람이 선을 넘는 것을 세는 기계"가 실제로 도는지 보기 위한 대리 장면이다.

## 무엇을 보고 세는가

**원본 영상을 보고 센다.** 예측이 그려진 `annotated.mp4`를 보고 세지 않는다.
모델이 그린 상자를 보면서 세면 모델이 놓친 사람을 나도 놓친다. 정답이
예측을 따라가면 오차는 줄어들고 그 숫자는 거짓이 된다.

## Occupancy 규칙

**ROI 안에 발이 있는 사람의 수를 센다.**

ROI = 정규화 좌표 (0.02, 0.22) ~ (0.98, 0.78)
    = 픽셀 (15, 127) ~ (753, 449)

1. **기준점은 발이다.** 상자의 아래쪽 가운데, 즉 지면에 닿는 지점. 파이프라인의
   `BOTTOM_CENTER` anchor와 같은 규칙이다. 머리가 ROI 안에 있어도 발이 밖이면
   세지 않는다.
2. **가려져 발이 안 보이면 위치를 추정한다.** 가로등 기둥이나 삼각대에 몸의
   일부가 가려진 사람은, 사람이라고 알아볼 수 있으면 세고 발 위치를 눈으로
   추정한다.
3. **화면 가장자리에 잘린 사람**은 사람이라고 알아볼 수 있고 발이 ROI 안이면
   센다.
4. **선 위에 서 있는 사람**도 ROI 안이면 occupancy에 센다. 선은 통과 계수용이지
   occupancy와 무관하다.
5. **세지 않는 것:** 차 안의 사람, 건물 창문 너머의 사람, 사람인지 확신할 수
   없는 원거리 얼룩, 그림자, 표지판, 마네킹.
6. **확신이 서지 않으면 세지 않는다.** 그리고 그 시점을 `notes`에 적는다.
   애매한 것을 세는 쪽으로 몰면 정답이 조용히 부풀려진다.

## Entry / Exit 규칙

**세로 counting line: x = 0.72 (픽셀 553), y 0.22 ~ 0.78.**

- 선의 **왼쪽**이 POSITIVE, **오른쪽**이 NEGATIVE다.
- **IN = 오른쪽에서 왼쪽으로 넘어가는 것** (`in_direction: POSITIVE`).
- **OUT = 왼쪽에서 오른쪽으로 넘어가는 것.**

이 장면에 실제 "입구"가 있는 것은 아니다. 정답과 예측이 같은 선, 같은 방향
규칙을 쓰기만 하면 계수 오차는 의미가 있다.

1. 1초 간격 시점들에서 각 사람의 **발 x좌표**가 553보다 왼쪽인지 오른쪽인지
   기록한다.
2. 연속한 두 시점 사이에서 좌우가 바뀌면 통과 사건 1회로 센다.
3. **ROI 세로 범위(y 127~449) 밖에서 선을 지나가는 사람은 세지 않는다.**
   파이프라인도 ROI 밖 상자를 버리므로 같은 조건이다.
4. 선 위에 서 있다가 원래 쪽으로 돌아가면 사건이 아니다.
5. 실제로 나갔다가 다시 들어오면 두 번 센다.

**이 방식의 한계를 미리 적어 둔다.** 1초 간격 표본으로 좌우 변화를 보므로,
두 표본 사이에 넘어갔다가 되돌아온 사람은 놓친다. 그리고 사람을 시점 사이에
이어 붙이는 것은 사람이 눈으로 하는 일이라 밀집 구간에서 틀릴 수 있다.
따라서 여기서 나온 입장 인원 정답은 **완전한 사건 단위 annotation이 아니라
1초 표본 기반 추정치**다. 보고서에도 그렇게 적는다.

## 눈가림(blind) 여부

완전한 blind annotation은 아니다. 같은 사람이 파이프라인을 만들고 정답을
붙였다. 다만 다음은 지켰다.

- 정답은 **원본 영상**만 보고 작성했다.
- 규칙을 예측보다 **먼저** 문서로 고정했다.
- 정답을 쓴 뒤에는 ROI도 선도 옮기지 않았다.

그래도 이것은 한 사람이 만든 한 벌의 정답이고, 독립적인 두 번째 annotator가
없다. 보고서의 한계에 적는다.
