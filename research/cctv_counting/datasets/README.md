## 정답 파일

`annotations/`에 헤더만 있는 템플릿 두 개를 두었다.

```
occupancy_ground_truth.csv
  video_id, frame_index, timestamp_seconds, actual_count, condition, annotator, notes

crossing_ground_truth.csv
  video_id, event_index, frame_index, timestamp_seconds, direction, condition, annotator, notes
```

occupancy와 entry는 다른 값이므로 정답도 하나로 합치지 않는다. 두 파일 모두
신원에 해당하는 열이 없다.

`condition` 열은 **비워 둘 수 있고, 비워 두는 것이 지어내는 것보다 낫다.**
비어 있으면 조건별 표에서 그 표본이 빠진다. 그것이 맞다.

`actual_count`를 프레임 전부에 붙일 필요는 없다. 일정 간격으로 뽑은 프레임만
세어도 MAE는 계산된다.

## 후보 조사

목적을 넷으로 나눈다.

```
A. Person Detection            사람 상자를 잘 찾는가
B. Multi-Object Tracking       프레임 사이를 잘 잇는가
C. Crowd / Occupancy Counting  많을 때 몇 명인지 아는가
D. Entry / Exit Counting       선을 넘은 사람을 세는가
```

D에 딱 맞는 공개 벤치마크는 사실상 없다. 대응 방안은 아래 "D를 어떻게 만들 것인가".

### 확인 상태를 먼저 정한다

라이선스를 표에 적을 때 **어디까지 확인한 것인지**를 같이 적는다. 추측으로
확정하면 나중에 그 칸이 근거처럼 쓰인다.

| 표시 | 뜻 |
|---|---|
| **VERIFIED** | 공식 페이지나 저장소 원문을 이번 조사에서 직접 읽었다 |
| **PARTIALLY VERIFIED** | 널리 알려진 내용과 일치하나 공식 원문 접근에 실패했다 |
| **UNVERIFIED** | 원문을 읽지 못했다. 받기 전에 확인해야 한다 |

그리고 **소프트웨어 라이선스와 데이터 이용 조건은 다른 문서다.** 이번 조사에서
바로 그 함정을 하나 만났다.

> CrowdHuman의 GitHub 저장소(`sshao0516/CrowdHuman`) LICENSE는 **MIT**다.
> 그런데 공식 다운로드 페이지의 데이터 이용 조건은 **비상업 연구·교육 전용,
> 재배포 금지**다. 저장소 라이선스를 데이터 라이선스로 읽으면 정반대 결론이
> 나온다.

MIT인 것은 그 저장소가 담고 있는 도구 코드이지 이미지가 아니다. 표의
라이선스 열은 **데이터 이용 조건**을 적는다.

### UNVERIFIED 항목은 받기 전에 확인한다

MOT17/MOT20은 이번 조사 시점에 `motchallenge.net` 접속이 되지 않아
(`ECONNREFUSED`) 공식 Terms 원문을 읽지 못했다. 비상업 조건이라는 것은 여러
2차 출처에서 일관되게 나오지만, **그것을 확정으로 적지 않는다.** 실제로 받기
전에 사이트의 Terms를 직접 읽는다.

PETS2009는 출처 접근성과 조건을 모두 확인하지 못했다. **확인 전까지 사용
후보에서 제외한다.**

## 상용 라이선스가 실질적 제약이다

CrowdHuman은 **비상업 조건**임이 확인되었고, MOT17/MOT20도 그럴 가능성이
높다(미확인). 그 조건이 뜻하는 바를 분명히 해 둔다.

**할 수 있는 것.** 연구·교육 목적으로 baseline 성능을 재고, 그 숫자를 포트폴리오
보고서에 싣는 것. 대학원 지원 자료로서의 용도는 이 조건 안에 들어간다.

**할 수 없는 것.** 이 데이터로 학습한 모델을 밥플래너 상용 서비스에 넣는 것.
이 데이터를 재배포하는 것.

그래서 이 데이터들은 **평가용으로만** 쓴다. fine-tuning은 나중에 상용 가능한
데이터(직접 수집한 급식소 영상, 또는 상용 허용 공개 데이터)로 한다.

detector 선택에서 Ultralytics를 제외한 것과 같은 판단이다. 나중에 버리게 될
결과는 처음부터 만들지 않는다. 다만 그쪽에서도 적었듯, torchvision을 고른
것은 "제약이 없어서"가 아니라 **가중치 층의 조건을 저장소가 명시해 두어
무엇을 확인해야 하는지 알 수 있기 때문**이다. 어느 쪽도 배포 자격을 여기서
결론 내지는 않는다.

## 첫 벤치마크 계획

**대규모 데이터셋 전체를 받지 않는다.** 평가에 필요한 만큼만 받는다.

첫 벤치마크 후보: **MOT17 학습 셋의 고정 카메라 시퀀스 1~2개.**

이유:

- 고정 카메라라 우리 CCTV 설치 조건과 가장 가깝다. 카메라가 움직이는
  시퀀스는 지금 pipeline의 가정(선과 ROI가 화면에 고정)과 맞지 않는다.
- track ID가 있으므로 정답 궤적에서 **entry counting 정답을 유도할 수 있다.**
- 시퀀스 하나가 수백~수천 프레임이라 사람이 직접 세는 것도 가능한 규모다.

받기 전에:

1. `motchallenge.net`의 Terms를 직접 읽고 비상업 조건을 확인한다.
2. 라이선스 동의가 필요하면 **정식 절차로 받는다.** 동의 절차를 우회하는
   미러나 재배포본을 쓰지 않는다.
3. 시퀀스 하나만 받는다.
4. `datasets/raw/`에 둔다. 이 경로는 `.gitignore`에 있다.

**받지 않기로 하는 조건.** 용량이 지나치게 크거나, 라이선스가 애매하거나,
수동 등록이 필요한데 그 절차를 밟을 수 없으면 억지로 받지 않는다. 그 경우
"pipeline 완성, 벤치마크 대기"로 끝낸다.

## D를 어떻게 만들 것인가

Entry/exit counting에 딱 맞는 공개 벤치마크가 사실상 없다. 두 가지 방법이 있다.

**(1) MOT 정답 궤적에서 유도한다.** MOT17에는 프레임별 사람 상자와 track ID가
있다. 화면에 선을 하나 긋고 **정답 궤적**이 그 선을 넘는 사건을 세면, 그것이
곧 entry counting의 정답이다. 예측은 우리 pipeline이 낸 값이다.

이 방법의 장점은 사람이 손으로 세지 않아도 정답이 나온다는 것이다. 한계는
그 정답이 "우리가 그은 선"에 대한 정답이라는 점이다. 선을 다른 데 그으면 정답이
바뀐다. 그래서 선의 위치를 `metadata.json`에 남긴다.

**(2) 사람이 직접 센다.** 영상을 보고 넘어간 사람을 센다. 실제 급식소 영상이
생기면 이쪽뿐이다.

첫 벤치마크에서는 (1)로 간다. 손으로 세는 비용 없이 시작할 수 있고, 정답의
근거가 코드로 남는다.

## Domain condition 태그

조건별 평가를 하려면 표본마다 태그가 필요하다.

```
daylight / low-light / sparse / crowded / occlusion / far-distance / oblique-camera
```

공개 데이터셋 대부분이 이 태그를 제공하지 않는다. MOT는 시퀀스 단위로 실내/실외,
낮/밤 정도의 설명이 있어서 시퀀스 전체에 태그를 붙이는 것은 가능하다.

**제공되지 않는 조건을 만들어 내지 않는다.** 사람이 직접 붙인 것은 `annotator`
열에 누가 붙였는지 남긴다. 조건을 모르는 표본은 `condition`을 비워 두고, 조건별
표에서 빠진다.

## 커밋 규칙

- 원시 데이터는 `datasets/raw/`에 두고 커밋하지 않는다.
- 실행 결과는 `outputs/` 또는 `experiments/`에 두고 커밋하지 않는다.
- 모델 weight는 라이브러리 캐시에 두고 커밋하지 않는다.
- 커밋하는 것: 이 README, 정답 파일 **템플릿**(헤더만), 설정 파일, 코드.
